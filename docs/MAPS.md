# 地图升级说明与验收

## 使用方式

本次采用 Leaflet 1.9.4 + OpenStreetMap 标准瓦片。Leaflet 的 JavaScript、CSS、图片、许可证全部随项目本地提供，无需 API Key、Node 构建或新增 Python 依赖。数据库不改表、不迁移、不清空，原有身份/班级/时间/电子围栏规则继续生效。

1. 教师创建页：获取当前位置或输入中心坐标，预览范围；半径和中心更新后图形同步变化。
2. 学生任务卡：展开“查看签到范围”加载地图。点击原有定位签到按钮才获取位置，随后显示橙色位置点。蓝圆是签到范围，橙色虚线圈是定位精度估计。
3. 教师结果页：选择一名已签到学生，查看该条记录的位置与范围关系；下拉只包含该任务目标班级的成功记录。
4. “重新加载地图”在底图失败后重新尝试；“回到范围”恢复视野。折叠后停止该地图瓦片加载。

底图请求失败或 8 秒未完成加载时显示失败提示与重试按钮。坐标超出底图有效纬度范围或围栏过大时显示无法展示提示。本地示意图及切换入口已移除；地图失败不影响服务器签到校验。

## 代码位置

- `templates/_map.html`：共用地图资源与范围组件。
- `templates/teacher/create.html`、`templates/teacher/results.html`、`templates/student/dashboard.html`：在现有页面中接入。
- `static/js/maps.js`：按需初始化、圆形覆盖物、位置/精度、失败提示与重试、输入联动。
- `static/js/location.js`：通过本地页面事件将原有当次定位传给地图；不新增定位请求。
- `static/css/maps.css`：在线地图、加载状态及窄窗口样式。
- `static/vendor/leaflet/`：原版 Leaflet 文件、BSD-2-Clause 许可证、下载来源与 SHA-256。
- `app.py`：Referrer-Policy 改为 strict-origin-when-cross-origin，满足 OSM 跨域来源要求，仅发送 origin，不发送完整业务路径。
- `tests/test_maps.py`：地图数据授权范围、位置隔离、静态资源与规则回归。

## 数据与网络

地图使用 WGS-84 输入，未混入高德 GCJ-02 坐标。后台继续使用现有 Haversine 公式，前端计算仅用于显示。本次学生位置只在当前页面展示，刷新后不作为实时位置恢复。

在线地图会请求所显示区域的 OSM 瓦片，服务方可由请求了解查看区域及网络来源；不发送学生姓名、账号或整张考勤表。底图署名保留，使用浏览器正常缓存；未开发瓦片预下载、缓存代理或离线地图包。程序只加载已展开地图，不后台遍历任务下载。

参考：[Leaflet API](https://leafletjs.com/reference.html)、[OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)。
