# 基于 Python 的在线考勤系统

大学企业实训课程项目。本机统一完成开发，使用 Flask + Flask-SQLAlchemy + SQLite + Jinja2 + 原生 JavaScript。地图使用本地 Leaflet 与在线 OpenStreetMap 底图，地图加载失败时提供提示和重试。没有 Node 构建和运行时 CDN 依赖。

功能：教师/学生登录与退出、教师按班级创建圆形围栏签到任务、学生浏览器定位签到、教师全班考勤与缺勤统计、学生个人成功记录与调整记录、教师学生信息管理（姓名和班级）、补签/撤销/恢复。独立学生表和教师表。后端同时校验身份、任务固定名单、时间、坐标和距离，所有 POST 启用 CSRF。

## Windows 安装与启动

已验证环境：Windows、PowerShell 7.6.5、Python 3.13.3。以下命令在项目根目录执行，直接调用虚拟环境 Python，无需激活脚本或修改 PowerShell 执行策略。

```powershell
cd E:\study\companytrain
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m scripts.init_db
.\.venv\Scripts\python.exe -m scripts.seed_data
.\.venv\Scripts\python.exe app.py
```

浏览器打开 <http://127.0.0.1:5000> 或 <http://localhost:5000>。一次演示建议统一使用同一地址。默认只监听 `127.0.0.1:5000`，debug 关闭。终端按 Ctrl+C 停止。当前开发机器已完成安装、初始化和演示数据准备，再次运行只需要最后一条启动命令。从 GitHub 新克隆时，请完整执行上述安装、初始化和演示数据命令；仓库不包含本地数据库或虚拟环境。

`requirements.txt` 固定四项直接依赖；`requirements-lock.txt` 记录本机实际验证的全部依赖版本。也可使用 `-r requirements.txt` 安装直接依赖并由 pip 解析间接依赖。依赖均安装在项目 `.venv` 内，不修改全局 Python。

本机 `py --list-paths` 中的 3.12 登记路径无法启动，已使用实际可用的 `python`（3.13.3）；若另一台机器的 `python` 不可用，请先安装可用 Python，再建立虚拟环境。

## 配置、数据与安全

- 数据文件：`instance/attendance.db`，SQLite 外键在每个连接启用。应用启动不自动建表/清库，先运行初始化脚本。
- 密码仅保存 Werkzeug 哈希；session 包含 role 与 user_id；创建教师和签到学生从 session 获取。前端额外传入身份、距离或成功状态不可信。
- 所有 POST（包括登录、退出、创建、JSON 签到）校验 CSRF；JSON 使用 `X-CSRFToken`。页面默认转义，不输出用户输入的原始 HTML。
- 只有成功记录进入 attendance_record；时间不符、围栏外、参数错误都不写记录。教师调整保存到独立日志，缺勤由任务固定名单减去有效签到名单计算。
- 数据库存无时区 UTC，界面输入和展示固定 UTC+08:00；不依赖操作系统时区。时间边界为闭区间，距离未取整比较。
- 缺少 SECRET_KEY 时随机生成开发密钥，进程重启会使旧登录/表单失效，请刷新重新登录。不会创建固定生产密钥。
- 本地 HTTP 的 Secure Cookie 默认关闭；可信 HTTPS 环境应设置 `COOKIE_SECURE=1`。请勿在普通 HTTP 下打开该项。
- `.env.example` 只作示例，**应用不自动加载 `.env`**。PowerShell 设置变量例子：

```powershell
# 可选：只设置当前终端进程及其子进程的环境变量，不修改全局系统设置。
$env:SECRET_KEY = (.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))")
$env:COOKIE_SECURE = "0"
.\.venv\Scripts\python.exe app.py
```

初始化脚本非破坏性：只创建不存在的表，不把 create_all 当迁移工具。对已有表检查缺失字段、唯一约束和外键；发现明显不兼容会停止并保留数据。它不是完整迁移器，也不保证自动识别所有旧字段类型/业务语义差异。本次管理升级使用 `scripts.upgrade_management` 先备份再新增四张表并补齐旧任务名单；不修改原始四表结构，不清库。初始化脚本可重复执行，已有任务名单不会重新计算。

## 常见问题

- **定位失败**：检查浏览器位置权限、Windows 位置服务、网络和设备定位能力。localhost 是受信任的本地开发上下文，但不能保证设备一定能定位。
- **手机访问不了或无法定位**：localhost 指手机自身；当前服务只监听电脑本机。普通 HTTP 局域网地址通常不能使用浏览器定位。手机需要可达服务和可信 HTTPS 等条件，本项目未自动部署、未创建隧道、未关闭浏览器安全机制。真实手机定位未实测。
- **示例任务提示围栏外**：示例坐标不是当前设备位置。请教师在真实地点重新获取中心创建任务，或使用明确标记的开发者工具模拟。
- **CSRF 失败**：刷新页面后重试。重启时随机密钥会变化；过期表单、不同 session 的 token 都会被拒绝。
- **登录后身份被切换**：同一浏览器的普通标签共享 Cookie；使用不同浏览器或隔离配置文件。
- **任务时间已过**：重新创建任务。重跑种子脚本不会修改已存在任务时间。
- **终端中文乱码**：可在当前 PowerShell 先执行 `$env:PYTHONIOENCODING = "utf-8"`，再运行脚本；网页与源文件使用 UTF-8。
- **5000 端口被占用**：先确认并停止你自己此前启动的本项目进程，不要盲目结束其他服务；也可执行 `.\.venv\Scripts\python.exe -m flask --app app:create_app run --host 127.0.0.1 --port 5001`。
- **首次出现 no such table**：在根目录执行初始化和演示数据命令。不要把其他工作目录中的数据库误当作本项目数据。

`app.py` 为应用工厂；`extensions.py` 管理数据库与 CSRF；`models.py` 定义原始四表及四张管理扩展表；`routes/` 按登录、教师、学生组织路由；`services/` 包含距离函数、时间转换、固定名单和有效签到计算；`templates/` 和 `static/` 为本地页面资源；`scripts/` 提供初始化和种子数据；`tests/` 为自动化测试；`docs/DEMO.md` 为答辩流程，`docs/TESTING.md` 记录实际验收。

## 地图展示升级

无需 API Key、无需额外安装 Python 包，直接使用本地 `static/vendor/leaflet/` 的 Leaflet 1.9.4。地图本身无需数据库迁移；学生管理升级需要执行下文的升级命令。启动命令不变。正在运行的旧进程需先 Ctrl+C 停止后重新启动并刷新浏览器；随机开发密钥变化时重新登录。

- 教师创建页：获取当前位置或输入中心坐标后，预览圆形签到范围；改变半径/坐标后自动更新。此版地图仅展示，不支持点击地图选点。
- 学生任务卡：点击“查看签到范围”展开地图。点击原有“定位并签到”后，显示本次位置、距离和定位精度。蓝圈是围栏，橙点是学生位置，橙色虚线圈是定位精度估计，不是额外允许范围。
- 教师结果页：展开范围，或通过下拉列表选择一条成功签到记录，查看该次位置。只提供当前教师当前任务有权查看的记录。
- 失败或 8 秒加载超时显示提示，点击“重新加载地图”重试；“回到范围”重新居中。折叠范围会停止该地图加载。
- 已移除本地示意图。极区或过大的围栏显示无法展示提示，所有图形仅作参考，最终签到结果仍由 Python 后端判定。
- 地图不会主动获取位置或持续追踪。学生页面不会加载其他学生的坐标；本次定位点仅在当前页面显示，不新增数据库字段。

在线底图请求 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`，会向 OSM 发送所显示区域的瓦片请求（可推知查看区域）、网络信息及本地站点 origin Referer，不发送姓名、学号或考勤表。它需要网络且无可用性保证。程序保留署名、遵守正常浏览器 HTTP 缓存，只请求当前地图视口，不批量抓取、不预下载离线瓦片。底图失败不会阻断定位签到。

资料：[Leaflet 文档](https://leafletjs.com/reference.html)、[OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)。第三方许可证与来源哈希在 `static/vendor/leaflet/`。

实现说明与本次地图浏览器验收见 [MAPS.md](docs/MAPS.md)。

## 界面与任务查找

教师和学生任务列表支持状态筛选、关键词搜索和一键清除。导航高亮当前页面；任务结果与个人记录页提供返回、刷新入口。签到完成后即时更新卡片状态和筛选结果，已签到任务可跳转个人记录。电脑和窄屏使用相应布局，禁用 JavaScript 时仍可浏览服务器返回的完整任务列表。

## 学生管理与签到调整

教师登录后进入顶部“学生管理”，按学号/姓名和当前班级查询学生，点击“管理学生”修改姓名或所属班级，填写原因后保存。班级可选现有名称或输入新名称。学生名册由所有教师共同维护；账号和密码不受影响。

签到调整入口有两处：考勤结果每行的“调整签到”，或学生详情中的本人任务列表。仅发布任务的教师有权操作，且目标学生必须在该任务固定名单中。支持教师补签、撤销签到、恢复原始状态；原因必填并向该学生展示。未开始的任务不能调整，已结束任务可以更正。

- **转班**只影响转班后新建的任务；已发布任务（包括尚未开始的任务）保留原名单。转班不会改变旧任务应到人数、隐藏旧考勤或自动加入新班级已发布的任务。
- **补签**立即记入统计，显示“教师补签”，时间为本次操作时间；不编造经纬度，不在地图生成位置点。
- **撤销**取消该任务的有效签到，原定位记录仍保留。学生不能自行覆盖教师决定。
- **恢复原始状态**取消人工覆盖；原本有定位记录则恢复已签到，没有原始定位记录则恢复未签到/缺勤。若任务仍在进行、无原始记录，学生可重新按正常定位规则签到。
- 修改人、操作时间、原因和历史均保留。修改页有版本校验，旧页面重复提交或数据已变化时提示刷新，不覆盖较新的修改。
